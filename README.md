# Прозрачная вакансия

Тестовое задание онлайн-отбора хакатона «КантКод». Команда **sarkazm**.

Сервис получает вакансии Калининградской области с портала «Работа в России»,
проверяет, насколько понятно описаны условия работы, и сохраняет отчёт в JSON:
какие сведения пропущены, где формулировка допускает разные трактовки и что
редактору вакансии уточнить у работодателя.

Отчёт можно смотреть в локальном веб-дашборде. Дополнительный сценарий —
отбор вакансий, готовых к публикации без доработки.

## Для жюри за минуту

Нужны Python 3.10+ и любая модель с OpenAI-совместимым API. Самый простой путь
без покупки аккаунта — локальная `qwen2.5:7b` через Ollama, она же стоит в
настройках по умолчанию.

```bash
python -m venv .venv
.venv\Scripts\activate                 # Windows; в Linux и macOS: source .venv/bin/activate
python -m pip install -r requirements.txt

ollama pull qwen2.5:7b                 # один раз; Ollama: https://ollama.com
python main.py --mode check --limit 10
python webapp.py                       # http://127.0.0.1:8000
```

`python main.py` без аргументов запускает проверочный режим на учебном файле
`data/kantkod_sample_vacancies.json` и пишет `output/report.json`. Кнопки
«Проверка» и «Живой прогон» в дашборде запускают тот же `main.py`.

Без модели отчёт не строится: шаг ИИ обязателен. Если модель недоступна для всех
вакансий, команда завершается с кодом 2 и не перезаписывает прошлый отчёт. Чтобы
посмотреть готовый результат без запуска модели, откройте
`examples/report_sample.json` и `examples/good_vacancies_sample.json`.

| Что | Где |
| --- | --- |
| Обработка начинается | `main.py`, функция `run_pipeline`; запуск `python main.py` |
| Рабочий режим и расписание | `python main.py --mode live`, `python main.py --mode schedule` |
| Загрузка данных | `fetcher.py`: API региона 39 постранично или локальный JSON |
| Шаг ИИ | `analyzer.py`: после правил модель ищет неоднозначности и противоречия |
| Правила | `rules.py`: нормализация карточки и очевидные пропуски |
| Модель | по умолчанию локальная `qwen2.5:7b` через Ollama; пример отчёта собран через OpenAI-совместимый API DeepSeek |
| Оценка | `scoring.py` и `market.py`: 0–100 баллов, объяснимые штрафы |
| Формат отчёта | раздел [«Формат отчёта»](#формат-отчёта) |
| Пример отчёта | `examples/report_sample.json` по учебному файлу `data/kantkod_sample_vacancies.json` |
| Дополнительный сценарий | вакансии, готовые к публикации: `examples/good_vacancies_sample.json` |
| Интерфейс | `webapp.py` и `web/`: дашборд без внешних зависимостей |

## Как это устроено

```
API «Работа в России» (регион 39)          локальный JSON в формате API
        │  live / schedule                          │  check
        └────────────────────┬───────────────────────┘
                             ▼
              fetcher.py — страницы offset/limit и дедупликация
                             ▼
        rules.py — чистая карточка и пропуски по обязательным полям
                             ▼
     analyzer.py — модель ищет неоднозначности и противоречия в тексте
                             ▼
   merge_issues — проверка ответа модели, дедупликация, лимит на тему
                             ▼
      scoring.py + market.py — оценка 0–100 и разбор компонентов
                             ▼
   reporter.py — output/report.json и output/good_vacancies.json
                             ▼
              webapp.py — локальный дашборд
```

Проверка идёт слоями:

1. **Правила** разбирают каждую вакансию всегда. Они убирают HTML, заглушки
   вроде «Не указано» и находят пропуски по обязательным полям.
2. **Модель** получает уже нормализованную карточку и добавляет то, для чего
   правил нет: расплывчатые формулировки и противоречия в свободном тексте.
3. **Ответ модели проверяется кодом.** Замечания с невалидной схемой
   отбрасываются, ложные пропуски по заполненным структурированным полям
   удаляются, повторы склеиваются. Если модель не ответила по отдельной
   вакансии, остаются замечания правил, а причина попадает в `analysis_error`.

## Запуск

### Установка

```bash
python -m pip install -r requirements.txt
```

Зависимости: `httpx`, `pydantic`, `python-dotenv`, `schedule`. Веб-дашборд
работает на стандартной библиотеке и отдельных пакетов не требует.

Настройки читаются из переменных окружения и файла `.env`. Образец —
`.env.example`; скопируйте его в `.env`, если хотите сменить модель или ключ:

```bash
copy .env.example .env        # Windows
cp .env.example .env          # Linux и macOS
```

Файл `.env` исключён из Git. Без `.env` проект использует значения по
умолчанию: локальную Ollama, учебный файл и `output/report.json`.

### Проверочный режим

Разбирает локальный JSON в формате ответов API, к порталу не обращается.

```bash
python main.py --mode check --input data/kantkod_sample_vacancies.json --output output/report.json --limit 10
```

- Подходит ответ списка (`results.vacancies[].vacancy`), ответ одной вакансии,
  массив таких ответов и голый массив вакансий.
- Вакансии с одинаковым ID объединяются: в отчёте остаётся один результат на ID.
- `--limit` ограничивает число вакансий и в проверочном режиме тоже. Чтобы
  обработать весь файл, задайте лимит не меньше числа вакансий в нём.
- `--output` задаёт путь отчёта, `--limit` — сколько вакансий взять.
- `--verbose` включает подробный лог.

Быстрая проверка на одной вакансии:

```bash
python main.py --mode check --limit 1
```

### Рабочий режим

```bash
python main.py --mode live --limit 40
```

Сервис читает API региона 39 постранично через `offset` и `limit` и сохраняет:

- `output/report.json` — текущий отчёт;
- `output/good_vacancies.json` — вакансии, готовые к публикации;
- `logs/run.log` — журнал прогона.

По умолчанию страница — 20 вакансий, максимум — 3 страницы и 40 вакансий,
поэтому один прогон проходит минимум две страницы. Пагинация останавливается,
когда API вернул пустую страницу, не дал новых записей или закончились данные.

**Сбой источника.** Если портал недоступен, отвечает ошибкой или не возвращает
ни одной вакансии, команда пишет ошибку в лог и завершается с кодом 1, не трогая
`output/report.json`. В нём остаётся последний успешный отчёт.

**Повторный запуск.** В отчёте всегда один объект на `vacancy_id`. Кэша нет:
неизменённые вакансии разбираются заново, но результат по каждому ID остаётся
единственным.

### Запуск по расписанию

```bash
python main.py --mode schedule
python main.py --schedule                  # то же самое
```

Планировщик сразу выполняет первый прогон, затем повторяет его каждые
`SCHEDULE_INTERVAL_MINUTES` минут (по умолчанию 60). Это интервал, а не
cron-выражение. Остановка — `Ctrl+C`.

Внешний планировщик тоже подойдёт: достаточно вызывать
`python main.py --mode live` из cron или «Планировщика заданий» Windows.

### Веб-дашборд

```bash
python webapp.py
python webapp.py --port 8080 --no-browser
```

Открывается `http://127.0.0.1:8000`. В интерфейсе есть:

- сводка: число вакансий, средняя оценка, распределение по grades и темам,
  сравнение оплаты со средней по региону;
- поиск по должности, работодателю и тексту замечаний;
- фильтры «Все», «Готовые», A, B, C, D и сортировка по оценке, замечаниям
  или названию;
- карточка вакансии: условия, из чего сложилась оценка, разбор графика и
  оплаты, штрафы и замечания;
- кнопки «Проверка» и «Живой прогон» с лимитом и журналом выполнения.

Дашборд запускает `main.py` отдельным процессом и читает готовые JSON-файлы.
Мини-API: `GET /api/report`, `GET /api/good`, `GET /api/summary`,
`GET /api/status`, `POST /api/run`.

## ИИ

**Шаг, на котором работает ИИ.** После правил каждая вакансия отправляется
модели (`analyzer.py`, метод `analyze_vacancy`). Модель читает нормализованную
карточку и возвращает замечания трёх видов: пропуск, неоднозначность,
противоречие. Её замечания попадают в отчёт с пометкой `"detected_by": "ai"`.
Пропуски по обязательным полям ищут и правила — они надёжнее и не тратят
токены модели.

**Модели и провайдеры.**

| Вариант | Что нужно | Настройки |
| --- | --- | --- |
| Локальная `qwen2.5:7b` через Ollama (по умолчанию, без покупки аккаунта) | установить Ollama и выполнить `ollama pull qwen2.5:7b` | `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen2.5:7b` |
| Облачная модель DeepSeek (на ней собран пример отчёта) | ключ провайдера | `LLM_BASE_URL=https://api.deepseek.com`, `LLM_API_KEY=<ключ>`, `LLM_MODEL=<модель>` |
| Любая другая модель | OpenAI-совместимый `/chat/completions` | свои `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |

Ключ хранится только в `.env` или переменной окружения. В репозитории ключа нет.
Для Ollama ключ не проверяется, поэтому подходит значение по умолчанию `ollama`.

**Ответу модели не верят на слово.** Обычный код проверяет:

- ответ — валидный JSON по схеме `VacancyAnalysisResult` (Pydantic): тема и вид
  замечания из фиксированного списка, непустые `problem` и `recommendation`;
- JSON извлекается даже из ответа в блоке ```json```;
- при ошибке формата делается ещё одна попытка с просьбой вернуть только JSON;
- замечание «пропуск» по заполненному структурированному полю (должность,
  график, занятость, оплата) удаляется;
- повторы по теме, виду и полю склеиваются;
- на одну тему остаётся не больше двух замечаний, всего — не больше 12;
- замечание с цитатой, которая целиком входит в другую цитату по той же теме,
  удаляется.

**Если модель недоступна.** Ошибка записывается в `analysis_error` вакансии,
а в отчёте остаются замечания правил. Если модель не ответила ни по одной
вакансии, отчёт не сохраняется и команда завершается с кодом 2, чтобы не
потерять прошлый результат.

**Скорость.** Запросы идут последовательно, по одной вакансии. Облачная модель
отвечает быстрее, локальная `qwen2.5:7b` на процессоре может разбирать десять
вакансий несколько минут. Таймаут одного ответа — `LLM_TIMEOUT_SECONDS`
(по умолчанию 60 секунд), при ответах 429/5xx делается до трёх попыток.

**Что модель не делает.** Она не добавляет факты, которых нет в карточке, и не
делает выводов о нарушении закона — это запрещено системным промптом. Определять
форму собственности работодателя по заданию не требуется.

## Что проверяется

Семь тем: название должности, обязанности, требования, оплата, график, место
работы, тип занятости. Учитываются и структурированные поля API, и тексты
`duty`, `requirements`, `requirement.qualification`.

Конкретные сведения в любом поле закрывают тему: отсутствие их повтора в
описании — не проблема. Например, «Полный рабочий день» в `schedule` не станет
замечанием из-за того, что в описании нет часов.

| Тема (`topic`) | Пропуск (правила) | Что добавляет ИИ |
| --- | --- | --- |
| `role_title` | пустое `job-name` | слишком общее название без конкретики; несоответствие названия обязанностям |
| `responsibilities` | пустое `duty` | общие слова без задач, «иные поручения», отсылка к должностной инструкции |
| `requirements` | пустые `requirements` и `requirement.qualification`; пустое `requirement.education`, если образование не упомянуто в тексте | неконкретные знания и навыки; противоречие опыта или образования между полем и текстом |
| `compensation` | нет суммы в `salary_min`, `salary_max` и `salary` | «по договорённости», зарплата словами, противоречие сумм |
| `schedule` | пустое `schedule` | «гибкий график» без дней и часов, сменный режим без схемы, противоречие с описанием |
| `location` | в `addresses` нет ни одного адреса | только город без улицы, удалёнка без условий, разные города в полях |
| `employment_type` | пустое `employment` | неполный тип занятости, противоречие с графиком или ставкой |

Правила ищут только очевидные пропуски. Неоднозначности и противоречия в
свободном тексте — задача модели.

**Виды замечаний.** `missing` — сведений нет; `ambiguity` — формулировку можно
понять по-разному; `contradiction` — два значения несовместимы, оба исходных
значения приводятся в `quote`.

## Формат входа

Проверочный режим принимает ответ API «Работа в России» в нескольких видах:

- `{"results": {"vacancies": [{"vacancy": {...}}, ...]}}`;
- `{"vacancy": {...}}` — одна вакансия;
- массив таких ответов или массив вакансий.

Используются поля: `id` (также `vacancy_id`, `uuid`, `code`), `vac_url` (также
`url`, `link`), `job-name`, `company.name`, `region.name`, `employment`,
`schedule`, `salary_min`, `salary_max`, `salary`, `currency`, `duty`,
`requirements`, `requirement.education`, `requirement.experience`,
`requirement.qualification`, `addresses.address[].location`.

Если ID нет, вакансия получает `unknown_<номер>`. Дубликаты по ID объединяются.

### Запись вакансии

| Поле | Значение |
| --- | --- |
| `vacancy_id` | ID вакансии из источника |
| `url` | ссылка на карточку (`vac_url`); `null`, если её нет |
| `vacancy` | компактная карточка: должность, работодатель, регион, зарплата, график, занятость, адреса |
| `issues` | массив замечаний; пустой, если замечаний нет |
| `analysis_error` | текст ошибки, если модель не разобрала вакансию; иначе `null` |
| `score` | оценка 0–100 |
| `grade` | `A`, `B`, `C` или `D` |
| `penalties` | штрафы к «понятности описания»: баллы и причина |
| `score_components` | три компонента оценки с весами и пояснением |
| `schedule_analysis` | разбор графика: тип, ясность, комфортность, дни, часы |
| `salary_analysis` | сравнение оплаты со средней по региону |

### Замечание (`issues[]`)

| Поле | Значение |
| --- | --- |
| `topic` | `role_title`, `responsibilities`, `requirements`, `compensation`, `schedule`, `location`, `employment_type` |
| `source_field` | поле источника, например `schedule` или `requirement.education` |
| `quote` | дословная цитата; у пропуска всегда пустая строка, у противоречия — оба значения |
| `issue_type` | `missing` — пропуск, `ambiguity` — неоднозначность, `contradiction` — противоречие |
| `problem` | суть проблемы; для пропуска — каких сведений не хватает |
| `recommendation` | что именно уточнить или дописать работодателю |
| `detected_by` | `rule` — нашло правило, `ai` — нашла модель |

### Оценка

Итог — взвешенная сумма трёх компонентов:

| Компонент | Вес | Как считается |
| --- | --- | --- |
| Понятность описания | 50% | 100 минус штрафы за пропуски и замечания ИИ |
| График работы | 25% | 0,6 × ясность + 0,4 × комфортность типа графика |
| Оплата к средней по региону | 25% | сравнение представительной зарплаты со средней по области |

Штрафы за понятность: нет оплаты −25, указана одна граница −8, нет адреса −12,
адрес неполный −6, нет графика −12, нет занятости −8, нет обязанностей −12,
нет требований −8, нет образования −4, противоречие ИИ −8, неоднозначность
ИИ −3, пропуск ИИ −5. Штрафы правил не дублируются: структурные пропуски уже
учтены выше.

Grades: `A` — от 85, `B` — от 70, `C` — от 50, `D` — ниже 50.
Округление — обычное, 0,5 вверх. Один и тот же вход всегда даёт один и тот же
результат.

**Рыночный ориентир.** Средняя начисленная зарплата в Калининградской области —
83 200 ₽ (Калининградстат, январь–август 2026), медиана предлагаемых зарплат —
70 000 ₽ (ГородРабот.ру, октябрь 2026), мода — 50 000 ₽. Среднюю и медиану можно
переопределить через `MARKET_AVG_SALARY` и `MARKET_MEDIAN_SALARY`.

**График.** Разбор в `market.py`: стандартная пятидневка, гибкий, сменный,
вахтовый, удалённый и частичный графики. Ясность зависит от наличия дней и
часов, комфортность — от типа графика и поправок за ночные, суточные и
12-часовые смены.

## Дополнительный сценарий: вакансии, готовые к публикации

**Кому помогает.** Редактору или рекрутёру, который просматривает отчёт: не
нужно вручную перебирать все вакансии, чтобы найти те, которые уже можно
публиковать или предлагать работодателю без доработки.

**Какие данные API использует.** Все поля вакансии, которые попадают в отчёт:
ID, ссылку, должность, работодателя, регион, зарплату, график, занятость,
адреса, а также замечания, штрафы и оценку.

**Какой результат выдаёт.** Отдельный файл `output/good_vacancies.json`:
компактные карточки вакансий, у которых анализ прошёл без ошибки и замечаний
не больше `GOOD_MAX_ISSUES` (по умолчанию 1). Сортировка — по убыванию оценки.
Новых фактов сценарий не добавляет: он только отбирает и переупаковывает уже
посчитанный результат.

```bash
python main.py --mode check --limit 10
python main.py --mode check --good-max-issues 0 --good-output output/strict.json
```

Пример — `examples/good_vacancies_sample.json`: 4 вакансии из 10 учебных.
В интерфейсе они видны по фильтру «Готовые».

## Как проверяли

```bash
python -m unittest discover -s tests -v
```

**Тесты.** 12 тестов в `tests/test_scoring.py` не ходят в сеть: проверяют
разбор графика, сравнение оплаты со средней, веса компонентов, итоговую сумму
и снижение оценки при пропусках.

**Учебные данные.** На `data/kantkod_sample_vacancies.json` (10 вакансий)
`examples/report_sample.json` содержит 25 замечаний: 18 от модели и 7 от
правил. Средняя оценка — 70,3; grades: 8 B, 1 C, 1 D. Четыре вакансии попали
в `examples/good_vacancies_sample.json`.

**Живые данные.** В `output/report.json` — прогон на 10 вакансиях региона:
4232 вакансии доступно в API, 28 замечаний, средняя оценка 66,5, сбоев модели
нет, одна вакансия готова к публикации. При лимите 40 и размере страницы 20
тот же процесс проходит две страницы.

**Интерфейс.** Проверены запуск дашборда, выдача страницы и сводки `/api/summary`;
кнопки запуска используют тот же `main.py`, проверенный в проверочном и живом
режимах.

## Ограничения

- Шаг ИИ обязателен: без модели команда не сохраняет отчёт. Отдельного флага
  «только правила» в CLI нет.
- Правила осторожны и находят только очевидные пропуски; смысловые
  неоднозначности и противоречия зависят от качества модели.
- `--limit` ограничивает и проверочный режим. Для полного файла задайте лимит
  не меньше числа вакансий.
- Кэша и запасных моделей нет: повторный прогон заново отправляет вакансии
  модели, при недоступности модели отчёт не обновляется.
- Запросы к модели идут последовательно; на локальной модели большой набор
  может обрабатываться долго.
- Рыночный ориентир — снимок на октябрь 2026; при устаревании его нужно
  обновить через переменные окружения.
- Расписание — интервал в минутах, а не cron-выражение.
- Дашборд слушает localhost и не имеет авторизации; для публичного доступа
  нужен отдельный reverse proxy и защита.
- Ответ модели проверяется по формату и дублям, но дословность цитаты
  автоматически не сверяется: возможны неточные формулировки.
